# Pluto 0.1.2 — one normal mode, app shortcuts and a refined console

Download `app-release.apk` from this release, open it on Android 11 or newer, and choose
**Update**. Your browser may need permission to install unknown apps.

## Changed

**Normal mode (portrait and landscape now work the same way)**
- Press and hold an app for a small menu beside it: the app's own shortcuts (New tab,
  New event, …) and Pin, Dock, Info, Hide and Uninstall, with More… for the full list.
  Shortcuts need Pluto to be the default Home app.
- Drawer search and category chips moved to the bottom, under the thumb. The back arrow is
  gone (swipe down or Back closes the drawer), and the chip row fades where it scrolls.
- Glass dock that takes the background's colour; empty slots fold away and come back while
  you drag an app.
- Landscape drops its toolbar and uses the same press-and-hold Home menu as portrait. The
  Home menu is opaque and closes when you leave the launcher.
- Haptic ticks while dragging over drop targets, and a confirmation on drop.
- New **Gestures** settings: what a swipe down on Home does (notifications, search or
  nothing) and an optional double-tap to lock (off by default; see below).
- The Pluto background holds the globe still with the heart facing you, keeps stars and
  shooting stars behind it, and uses a true-black sky.

**Console mode**
- Bigger cards, a shorter and fainter reflection, a flow that thins out at its edges,
  tabs that fade well clear of the clock, and a touch hint when no controller is in use.
- The button legend follows focus; the tab row wraps with the D-pad as with L1/R1; quick
  L1/R1 presses hand over smoothly; every connected controller's battery is shown.
- Right-to-left languages mirror the flow, tabs, shoulder buttons and clock.
- Fixed: focus lost after emptying a shelf or switching shelf from Edit, a recomposition
  on every D-pad step, stale card art after app updates, the focus glow never drawing,
  the status bar flipping under Settings, clipped empty-shelf buttons, and the selection
  not carried over when a controller connects.

## Permissions

Double-tap to lock uses an accessibility service, "Pluto screen lock", because that is the
only way Android lets a launcher lock the screen without disabling fingerprint unlock. It
is off unless you turn it on, it performs the lock and nothing else, listens to no events
and cannot read the screen.

## Verification and limits

- 237 JVM tests passed. Release (R8) build checked on the Android 16 emulator in portrait,
  landscape, console mode and right-to-left.
- Controller-only behaviour (focus fixes, legend, tab wrap, multiple batteries) and drag
  haptics still need confirmation on the phone with a controller.

## Updating safely

Android package: `dev.pluto.launcher`; version code: **3**; version name: **0.1.2**.
The APK uses the maintainer's local Android development signing key (certificate SHA-256
`55:65:39:7D:…:8B:13`), not a production/store key.

**This is a different key from the one that signed the 0.1.1 APK on this page**
(`C8:3F:3F:68:…:E8:5B`). Android can update an existing Pluto installation only if its
signing key matches, so a Pluto installed from the 0.1.1 release cannot update to this
one in place. If Android reports a signature conflict, do **not** uninstall a daily-use
build merely to bypass it: uninstalling deletes Pluto's local organisation and
preferences.
