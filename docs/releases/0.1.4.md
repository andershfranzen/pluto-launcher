# Pluto 0.1.4 — built-in updates and softer glass

Download `app-release.apk` from this release, open it on Android 11 or newer, and choose
**Update**. Your browser may need permission to install unknown apps. Pluto 0.1.3 and
earlier need this manual update once; this release adds the built-in updater for future
releases.

## Changed

**Built-in GitHub updates**
- On first opening this version, Pluto asks **Keep Pluto up to date?** Automatic checks
  are the default choice, but no GitHub request is sent until you answer. Choose
  **Allow automatic checks** or **No thanks**, and change your choice later in
  **Settings → General → Updates**.
- Allowed automatic checks run at most once a day when you open Pluto. Failed requests
  also back off, and Pluto remembers the last release information. There is no
  always-running background updater. A notice points you to Settings when a new stable
  release is available.
- Check manually, read release notes or choose **Download and update** from Settings.
  Downloads show progress and can be cancelled; completed downloads survive restarting
  the launcher.
- Pluto checks the APK's size, SHA-256 checksum, package, version and signing identity
  before handing a private read-only file URI to Android's installer. Different signing
  keys are rejected rather than risking your layout.
- Android may ask you to allow Pluto under **Install unknown apps**, then asks you to
  approve installation. Pluto continues when you return from granting permission;
  **Install update** lets you retry a downloaded update after cancelling.
- Internet and package-install permissions now support this optional feature. No app
  usage, ROM lists or launcher organisation are sent to GitHub. Ordinary launcher and
  ROM features continue to work offline.

**A calmer glass design**
- The update question is a compact glass dialog with the Pluto planet logo, short
  explanations and clear choices. Portrait centers the logo; landscape uses a compact
  header beside it.
- Glass panels over XMB take a subtle tint from the selected background colour, with
  less white opacity and softer borders. Settings cards avoid stacking bright fills,
  and stronger secondary text keeps descriptions readable.
- The treatment follows XMB colours, including Auto; orange and blue were visually
  checked. Pluto and wallpaper surfaces keep their neutral treatment.

## Verification and limits

- 251 JVM tests passed. Five focused Android tests covered first-launch consent,
  daily-check throttling, release metadata, checksum/version rejection and read-only
  installer file access.
- The R8 release built successfully. Portrait and landscape dialogs were visually
  reviewed, and live automatic and manual GitHub checks correctly identified the
  current release.
- Installation always requires Android's approval. Real phone/controller checks and
  a future-release installation on the OnePlus remain outstanding.

## Updating safely

Android package: `dev.pluto.launcher`; version code: **5**; version name: **0.1.4**.
The APK uses the same Android development signing key as **0.1.2 and 0.1.3** (certificate
SHA-256 `55:65:39:7D:43:DC:5E:5B:CA:F8:81:02:FD:3F:D3:C4:75:2D:6D:00:D1:33:29:75:93:BC:F5:79:0E:77:8B:13`).
Updating those releases preserves your layout and preferences.

The 0.1.1 release used a different signing key. If Android reports a signature conflict,
do **not** uninstall a daily-use build merely to bypass it: uninstalling deletes Pluto's
local organisation and preferences.
